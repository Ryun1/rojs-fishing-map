# Phase 3: Evidence-based species model — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the old species score (temperature gate, harbour/rock flag, wind) with the spec 7.5 model: shore catch rate × season × time of day × fit to the spot × a small conditions adjustment, each part labelled measured, estimated or lore.

**Architecture:** Everything stays in `index.html` (one IIFE, ES5). The score stays `scoreFor(sp, spot, ctx) -> {score 0-100, why, f, ...}`, so every caller (ranked spots, best times, grid, summary) keeps working. New numbers live in `data/species.json` and `data/spots.json`; the sea temperature normal for each day ships as `data/sst-normal.json`, generated by `tools/sst_normal.py` from the research climatology.

**Tech Stack:** Plain HTML/CSS/ES5 JS, no build, no dependencies. Python 3 standard library for the one-off tool. Browser tests via `?test` and `playwright-cli` (see `tests/README.md`).

**Spec:** `docs/superpowers/specs/2026-11-22-spot-forecast-design.md`, section 7.5 (species likelihood). Read 7.5, the "Which app parameters have measured support" table in `docs/research/species.md` (section 3.3) and its section 7 tiering before starting.

## Decisions made in this plan (calls, to list for the owner)

1. **Score = 100 × base × season × time × habitat × conditions**, rounded and clamped to 0–100; Unsafe still caps it at 15. Multiplying (not adding) is what makes scores comparable across species: a rarely-shore-caught fish cannot score high just by being in season, and veja after dark scores 0.
2. **Base rate (estimated)**, ordered by the tiering in `docs/research/species.md` §7, but kept close together because Roj has caught all seven from the shore (owner, 2026-11-24): sargo 1.0, veja 0.9, bicuda 0.85, anchova 0.8, moreia 0.75, írio 0.65, serra 0.6. Every fish can reach at least Possible at its peak; the rarer ones rank a little lower than the everyday ones, they are not ruled out.
3. **Time of day** replaces the current weights with the research (labels per species): sargo dawn 0.9 / day 1 / dusk 0.8 / night 0.4 (measured); veja 0.5 / 1 / 0.5 / 0 (measured); bicuda 1 / 0.6 / 1 / 0.4 (measured); moreia 0.5 / 0.2 / 0.7 / 1 (measured); anchova 1 / 0.7 / 1 / 0.4 (estimated); írio 1 / 0.8 / 1 / 0.3 (estimated); serra 1 / 0.7 / 0.9 / 0.1 (estimated).
4. **Habitat fit (estimated)** = depth fit × the existing `kind[spot.type]`. Steepness `steep = clamp((1500 − d50) / 1200, 0, 1)` from the distance to the 50 m depth (null → 0). Each species has `deep` from −1 (wants a shallow shelf) to 1 (wants deep water close in): depth fit = `deep ≥ 0 ? 1 − deep × (1 − steep) : 1 + deep × steep`. Values: írio 0.5, serra 0.5, bicuda 0.4, anchova 0.4, moreia 0, sargo −0.2, veja −0.3.
5. **Conditions** = 1 + temperature + swell + tide, so 0.8 to 1.1:
   - temperature (estimated): anomaly `a` = sea temperature − the 1991–2020 normal for the date; 0 when unknown or `|a| < 1`; else `warm × clamp(a, −2, 2) × 0.05`. `warm`: írio, anchova, bicuda, serra 1; veja 0.5; moreia 0; sargo −0.5.
   - swell (lore): `0.1 × (band(eff, wave…) − 1)` with the existing `wave` band.
   - tide (lore): `0.05 × (tideWeight − 1)` with the existing `tide.move` / `tide.slack`.
6. **Wind leaves the species score** (fishability already covers it). The `t` (temperature band) and `wind` fields leave `species.json`.
7. **Season is labelled measured** (from the landings), with the existing "boat landings" caveat kept in the how-to text.
8. **The 0–100 number and the Likely / Possible / Unlikely words stay** as the UI review made them; the spec's five-dot scale is not brought back.
9. **No forecast**: species are ranked by `base × season`, not season alone.
10. **Sea temperature normal**: the mean of the six OISST cells around Pico, one value per day of year (day 366 uses day 365), one decimal.

## Review Focus

1. **Sea temperature missing** (manual mode with the field blank, or a forecast hour without SST): no anomaly, no crash, the breakdown says the temperature is unknown → Task 2 test `missing sea temperature`.
2. **31 December in a leap year (day 366)**: the normal lookup must not return `undefined` and turn the score into NaN → Task 1 test `normal on day 366`.
3. **A zero factor** (veja after dark): score 0, and the reason says it does not feed after dark rather than a generic line → Task 2 test `veja at night`.
4. **Unsafe cap still applies** with the new formula → Task 2 test `unsafe cap`.
5. **Scores stay within 0–100 for every species, spot and phase**, including the +10% conditions boost → Task 2 test `score range`.

- Produces:
  - `ctxFor(when, cc) -> {month, anom: number|null, eff, phase, moving, danger, sun}`; `anom` = `cc.raw.sst − sstNormal(when.y, when.month, when.d)` to 1 decimal, or `null` when `cc.raw.sst == null`. `temp` and `wind` are gone (no more default of 19).

    - cond: the most negative of `adj`: temp → `Sea <|a|> °C cooler than normal for the date (estimated).` or `… warmer …` (whichever the sign of `a` is); wave → existing wave texts with ` (angler lore)`; tide → `Slack tide, it prefers moving water (angler lore).`
